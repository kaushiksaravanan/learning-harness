## Unseen-problem transfer evidence

Only count a problem as transfer evidence if the learner has not previously seen its solution and did not receive a pattern-revealing cue before attempting. Record timed and untimed attempts separately. Keep recognition, proof, complexity, implementation, and result distinct; do not collapse them into one mastery score.

Hint level: `0` no hint; `1` open checkpoint; `2` constraint or invariant question; `3` trigger-only pattern cue; `4` partial proof/state step; `5` pseudocode step.

| Date | Problem / link | Target or contrast pattern | Unseen? / delay | Difficulty | Mode | Hint level | Recalled pattern unaided? | Justified applicability? | Proof / complexity sound? | Accepted? | Time | Failure or next action |
|---|---|---|---|---|---|---:|---|---|---|---|---:|---|
| | | | | | untimed | 0 | | | | | | |

At review time, summarize a pattern with the number of eligible attempts and the outcomes (for example, `2/3 unaided recognition; 1/3 full proof and solve`). Do not infer a trend from one attempt. A transfer check is evidence about performance on those problems, not proof of general expertise.
